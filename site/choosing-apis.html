入门

在 Graph API 与 Functional API 之间选择

新工作流优先使用 LangGraph Graph API。在为 LangSmith Deployment 封装其他框架时，请使用 Functional API。

LangGraph 为智能体工作流提供两套 API：Graph API 与 Functional API。两者共享同一运行时（持久化、流式输出、人在回路和记忆）。

Graph API 是默认选择。新建 LangGraph 智能体，以及任何能从显式状态、分支或图可视化中获益的工作流，都优先使用它。

当你需要在 LangSmith Deployment 上部署其他框架时，请使用 Functional API。用 @entrypoint 和 @task 封装现有的 Claude Agent SDK、Strands、CrewAI、AutoGen 或类似智能体，使 Agent Server 能以持久化、流式输出和追踪的方式运行它。

Graph API（默认）#

当你直接基于 LangGraph 构建时，请选择 Graph API：

  • 跨节点显式共享的状态
  • 条件分支，以及稍后汇聚的并行路径
  • 用于调试和文档的图示意图
  • 团队对工作流结构的评审

可以从 Graph API 构建检查清单或用 Graph API 思考开始。

Functional API（其他框架）#

当你已有其他框架中的智能体，并希望获得 LangSmith Deployment 的功能、又不想把该智能体重写为图时，请选择 Functional API：

  • 对现有过程式代码或框架代码的改动最小
  • 标准控制流（if/else、循环、函数调用）
  • 以函数作用域内的值为单位，而非共享状态模式

关于封装并部署的模式，请参见部署其他框架。关于 Functional API 的概念与操作指南，请参见 Functional API 概览。

并排形态对比#

同一个小工作流在两套 API 中写法不同。下面的示例先对一个数字分类，然后返回一条消息：

python
from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    number: int
    is_even: bool
    message: str


def check_even(state: State):
    return {"is_even": state["number"] % 2 == 0}


def format_message(state: State):
    return {
        "message": (
            "The number is even." if state["is_even"] else "The number is odd."
        )
    }


workflow = StateGraph(State)
workflow.add_node("check_even", check_even)
workflow.add_node("format_message", format_message)
workflow.add_edge(START, "check_even")
workflow.add_edge("check_even", "format_message")
workflow.add_edge("format_message", END)
graph = workflow.compile()

graph.invoke({"number": 7})
python
from langgraph.func import entrypoint, task


@task
def is_even(number: int) -> bool:
    return number % 2 == 0


@task
def format_message(is_even: bool) -> str:
    return "The number is even." if is_even else "The number is odd."


@entrypoint()
def workflow(inputs: dict) -> str:
    even = is_even(inputs["number"]).result()
    return format_message(even).result()


workflow.invoke({"number": 7})

Graph API 让状态与转换变得显式。Functional API 保留普通的控制流，并在任务之间传递值。

关注点Graph APIFunctional API
风格声明式的节点、边和共享状态命令式函数，配合 @entrypoint / @task（Python）或 entrypoint / task（TypeScript）
控制流边和条件边语言原生的 if/else、循环和调用
状态显式的状态与归并函数作用域限于入口点和任务
检查点每个超步后生成新检查点任务结果保存到入口点检查点
可视化一等公民的图示意图没有静态图可视化（图在运行时构建）
最适用场景LangGraph 工作流的默认选择为部署而封装其他框架

当线性的 Functional API 子工作流位于 Graph API 协调器内部，或反过来时，你仍然可以在同一个应用中组合这两套 API。
