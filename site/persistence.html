LangGraph/核心能力/持久化
核心能力

持久化

LangGraph 的持久化层通过检查点保存器为智能体提供短期记忆，并通过存储提供长期记忆。

持久化让 LangGraph 应用能够在单次图运行之外保留有用的信息。当智能体需要延续对话、从中断中恢复、从故障中恢复，或跨多次交互记住信息时，持久化就显得很重要。

LangGraph 提供两套互补的持久化系统：

  • Checkpointers 将线程的图状态持久化为检查点。用于短期、线程范围的记忆，包括对话连续性、人在回路工作流、时间旅行和容错。
  • Stores 在图状态之外持久化应用定义的数据。用于长期、跨线程的记忆，包括用户偏好、事实和共享知识。

大多数应用可以同时使用两者：检查点保存器跟踪当前线程，存储跟踪跨线程的持久信息。

快速开始#

使用检查点保存器、存储或两者来编译你的图：

python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore

checkpointer = InMemorySaver()
store = InMemoryStore()

graph = builder.compile(checkpointer=checkpointer, store=store)

result = graph.invoke(
    {"messages": [{"role": "user", "content": "Hi, my name is Bob."}]},
    {"configurable": {"thread_id": "thread-1"}},
)
ℹ注意

Agent Server 会自动处理持久化 使用 Agent Server 时，你无需手动实现或配置检查点保存器或存储。服务器会在后台处理持久化基础设施。

常见问题排查#

PostgresSaver：thread_id 过长#

使用 PostgresSaver（或 AsyncPostgresSaver）时，thread_id 存储在一个长度有限的列中。如果你的 thread_id 超过该列的长度，就会看到数据库错误。

修复： 将 thread_id 的值控制在 255 个字符以内。如果需要确定性 ID，请使用 UUID 或哈希：

python
from langchain_core.utils.uuid import uuid7
config = {"configurable": {"thread_id": str(uuid7())[:255]}}

MemorySaver 在重启之间不会持久化#

MemorySaver 和 InMemorySaver 将检查点存储在 RAM 中。进程重启时，所有检查点都会丢失。

修复： 生产环境中请使用持久化的检查点保存器：

  • PostgresSaver：支持异步的 PostgreSQL
  • SqliteSaver：用于开发的本地文件存储

检查点无限增长#

在长对话中，检查点会不断累积。这可能增加延迟和存储成本。

修复： 定期清理旧检查点，或设置保留策略：

python
from langgraph.checkpoint.postgres import PostgresSaver

checkpointer = PostgresSaver.from_conn_string("postgresql://...")
checkpointer.setup()  # Creates tables with indexes
# Consider adding a cron job to delete checkpoints older than N days

从父图访问子图的状态#

当子图更新状态时，父图可能不会立即看到这些变化。这是因为每个子图管理自己的检查点命名空间。

修复： 对需要跨图边界的数据使用通过存储共享状态，或将子图配置为写入父检查点。

后续步骤#

  • 使用检查点保存器来持久化并检查线程状态。
  • 使用存储来跨线程持久化需要长期保留的数据。
