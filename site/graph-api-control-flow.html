使用 Graph API 构建

构建序列、分支与循环

使用 LangGraph Graph API 组合序列、并行分支、条件边与循环。

使用 Graph API 组合序列、并行分支、条件边与循环。有关 map-reduce 扇出以及从节点返回边的信息，请参阅使用 Send 和 Command。有关节点级重试、超时与缓存的信息，请参阅配置节点。

创建步骤序列#

ℹ注意

前提条件 本指南假定你熟悉定义和更新状态。

本节展示如何构建顺序图。Python 还提供了用于同一模式的 add_sequence 简写。

mermaid
%%{init:{'theme':'base','themeVariables':{'lineColor':'#40668D','primaryColor':'#E5F4FF','primaryTextColor':'#030710','primaryBorderColor':'#006DDD'}}}%%
flowchart LR
    startNode([START]) --> s1[step_1]
    s1 --> s2[step_2]
    s2 --> s3[step_3]

    classDef process fill:#E5F4FF,stroke:#006DDD,stroke-width:2px,color:#030710
    classDef terminal fill:#F2FAFF,stroke:#40668D,stroke-width:2px,color:#030710
    class s1,s2,s3 process
    class startNode terminal

在 StateGraph 上使用 0 和 1 添加节点序列：

python
from langgraph.graph import START, StateGraph

builder = StateGraph(State)

# Add nodes
builder.add_node(step_1)
builder.add_node(step_2)
builder.add_node(step_3)

# Add edges
builder.add_edge(START, "step_1")
builder.add_edge("step_1", "step_2")
builder.add_edge("step_2", "step_3")

或者使用内置简写 .add_sequence：

python
builder = StateGraph(State).add_sequence([step_1, step_2, step_3])
builder.add_edge(START, "step_1")
为什么要使用 LangGraph 将应用步骤拆分为序列？

LangGraph 可以在图的下方添加持久化层。状态会在节点之间生成检查点，因此这些节点决定了：

  • 如何对状态更新创建检查点
  • 中断如何在人在回路工作流中恢复
  • 如何使用时间旅行回滚并分支执行

它们还决定了步骤如何流式输出，以及应用如何在 Studio 中可视化和调试。

以下端到端示例构建了一个包含三个步骤的序列：

  1. 在状态的一个键中填充值
  2. 更新同一个值
  3. 填充另一个值

首先定义状态。关于更新如何合并，请参阅使用归并函数处理状态更新。

此示例跟踪两个值：

python
from typing_extensions import TypedDict


class State(TypedDict):
    value_1: str
    value_2: int

节点是读取图状态并返回更新的 Python 函数。第一个参数始终是状态：

python
def step_1(state: State):
    return {"value_1": "a"}


def step_2(state: State):
    current_value_1 = state["value_1"]
    return {"value_1": f"{current_value_1} b"}


def step_3(state: State):
    return {"value_2": 10}
ℹ注意

每个节点的更新只需指定其更改的键。

默认情况下，这会覆盖这些键的先前值。如果更新应当追加或合并，请使用归并函数。请参阅使用归并函数处理状态更新。

接下来，在该状态上定义 StateGraph，并连接各个节点。

使用 0 和 1 填充图并定义其控制流。

python
from langgraph.graph import START, StateGraph

builder = StateGraph(State)

# Add nodes
builder.add_node(step_1)
builder.add_node(step_2)
builder.add_node(step_3)

# Add edges
builder.add_edge(START, "step_1")
builder.add_edge("step_1", "step_2")
builder.add_edge("step_2", "step_3")
💡提示

指定自定义名称 将显式名称作为第一个参数传递给 0：

python
builder.add_node("my_node", step_1)

请注意：

  • 0 接收节点名称。对于裸函数，默认名称是 node.__name__。
  • 图需要一个入口点：从 START 节点添加一条边。
  • 当没有更多节点要执行时，图会停止。

然后编译图。编译会运行基本结构检查（例如孤立节点）。当应用需要持久化时，在此处传入检查点保存器。

python
graph = builder.compile()

调用图：

python
graph.invoke({"value_1": "c"})
text
{'value_1': 'a b', 'value_2': 10}

请注意：

  • 这次调用为一个状态键传入了值。节点也可以写入输入中不存在的键。
  • 第一个节点会覆盖传入的值。
  • 第二个节点会更新该值。
  • 第三个节点会填充另一个键。
💡提示

内置简写 langgraph>=0.2.46 包含用于添加节点序列的内置简写 add_sequence。你可以按如下方式编译同一个图：

python
builder = StateGraph(State).add_sequence([step_1, step_2, step_3])
builder.add_edge(START, "step_1")

graph = builder.compile()

graph.invoke({"value_1": "c"})

创建分支#

并行节点执行可以加快图的运行速度。LangGraph 通过标准边和 conditional\_edges 实现扇出与扇入。以下示例构建分支数据流。关于面向动态目标的 map-reduce 扇出，参见使用 Send 和 Command。

并行运行图节点#

此示例从 Node A 扇出到 B 和 C，再扇入到 D。状态使用归并函数，使该键的值不断累积而不是被覆盖。对于列表而言，这意味着把新列表拼接到现有列表上。参见使用归并函数处理状态更新。

mermaid
%%{init:{'theme':'base','themeVariables':{'lineColor':'#40668D','primaryColor':'#E5F4FF','primaryTextColor':'#030710','primaryBorderColor':'#006DDD'}}}%%
flowchart LR
    startNode([START]) --> a[a]
    a --> b[b]
    a --> c[c]
    b --> d[d]
    c --> d
    d --> endNode([END])

    classDef process fill:#E5F4FF,stroke:#006DDD,stroke-width:2px,color:#030710
    classDef terminal fill:#F2FAFF,stroke:#40668D,stroke-width:2px,color:#030710
    class a,b,c,d process
    class startNode,endNode terminal
python
import operator
from typing import Annotated

from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    # The operator.add reducer fn makes this append-only
    aggregate: Annotated[list, operator.add]


def a(state: State):
    print(f'Adding "A" to {state["aggregate"]}')
    return {"aggregate": ["A"]}


def b(state: State):
    print(f'Adding "B" to {state["aggregate"]}')
    return {"aggregate": ["B"]}


def c(state: State):
    print(f'Adding "C" to {state["aggregate"]}')
    return {"aggregate": ["C"]}


def d(state: State):
    print(f'Adding "D" to {state["aggregate"]}')
    return {"aggregate": ["D"]}


builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(c)
builder.add_node(d)
builder.add_edge(START, "a")
builder.add_edge("a", "b")
builder.add_edge("a", "c")
builder.add_edge("b", "d")
builder.add_edge("c", "d")
builder.add_edge("d", END)
graph = builder.compile()

使用归并函数后，可以看到每个节点中添加的值都被累积起来。

python
graph.invoke({"aggregate": []}, {"configurable": {"thread_id": "foo"}})
text
Adding "A" to []
Adding "B" to ['A']
Adding "C" to ['A']
Adding "D" to ['A', 'B', 'C']
ℹ注意

在上面的示例中，节点 "b" 和 "c" 在同一个超步中并发执行。由于它们处于同一步，节点 "d" 会在 "b" 和 "c" 都完成后才执行。

重要的是，来自并行超步的更新顺序可能并不一致。如果你需要并行超步的更新具有一致且预先确定的顺序，就应该把输出写入状态中一个单独的字段，并同时写入用于排序的值。

异常处理

LangGraph 在超步中运行节点。一个超步中的并行分支会并发运行，但该超步是事务性的：只要任一分支抛出异常，该超步的更新就不会有任何一项应用到状态。

使用检查点保存器时，已完成超步中成功节点的结果会被保存，运行恢复时不会重复执行。

对于不可靠的 API 调用这类易出错的工作，可以使用以下任一方式：

  1. 在节点内部使用普通的 try / except（或等价写法）。
  2. 在节点上设置 0，让 LangGraph 重试指定的异常。只有失败的分支会重试，因此成功的同级分支不会重新运行。

这两者结合，可以在保持并行执行的同时让你控制失败的处理方式。完整指南参见容错。

💡提示

设置最大并发数 在调用图时，将 max_concurrency 作为顶层配置键传入（不要放在 configurable 下）。参见 RunnableConfig。

python
graph.invoke({"value_1": "c"}, {"max_concurrency": 10})

延迟节点执行#

延迟节点执行会把某个节点推迟到所有其他待处理任务完成之后。当各分支长度不同时这一点很重要，而这在 map-reduce 工作流中很常见。

上面的并行示例在每条路径都是一步时进行扇出和扇入。在 "b" 分支上添加一个节点 "b_2"，使各路径长度不相等。节点 d 使用 defer，因此它会等待更长的分支：

mermaid
%%{init:{'theme':'base','themeVariables':{'lineColor':'#40668D','primaryColor':'#E5F4FF','primaryTextColor':'#030710','primaryBorderColor':'#006DDD'}}}%%
flowchart LR
    startNode([START]) --> a[a]
    a --> b[b]
    a --> c[c]
    b --> b2[b_2]
    b2 --> d[d]
    c --> d
    d --> endNode([END])

    classDef process fill:#E5F4FF,stroke:#006DDD,stroke-width:2px,color:#030710
    classDef terminal fill:#F2FAFF,stroke:#40668D,stroke-width:2px,color:#030710
    class a,b,b2,c,d process
    class startNode,endNode terminal
python
import operator
from typing import Annotated

from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    # The operator.add reducer fn makes this append-only
    aggregate: Annotated[list, operator.add]


def a(state: State):
    print(f'Adding "A" to {state["aggregate"]}')
    return {"aggregate": ["A"]}


def b(state: State):
    print(f'Adding "B" to {state["aggregate"]}')
    return {"aggregate": ["B"]}


def b_2(state: State):
    print(f'Adding "B_2" to {state["aggregate"]}')
    return {"aggregate": ["B_2"]}


def c(state: State):
    print(f'Adding "C" to {state["aggregate"]}')
    return {"aggregate": ["C"]}


def d(state: State):
    print(f'Adding "D" to {state["aggregate"]}')
    return {"aggregate": ["D"]}


builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(b_2)
builder.add_node(c)
builder.add_node(d, defer=True)
builder.add_edge(START, "a")
builder.add_edge("a", "b")
builder.add_edge("a", "c")
builder.add_edge("b", "b_2")
builder.add_edge("b_2", "d")
builder.add_edge("c", "d")
builder.add_edge("d", END)
graph = builder.compile()
python
graph.invoke({"aggregate": []})
text
Adding "A" to []
Adding "B" to ['A']
Adding "C" to ['A']
Adding "B_2" to ['A', 'B', 'C']
Adding "D" to ['A', 'B', 'C', 'B_2']

节点 "b" 和 "c" 在同一个超步中并发运行。节点 d 上的 defer=True 使其在所有待处理任务完成之前不会运行，因此 "d" 会等待完整的 "b" 分支。

当每个分支总会运行时，你可以用列表形式的边来等待，而不必使用 defer=True。add_edge 也接受起始节点列表。这并不是分别调用 add_edge 的简写；两种形式的行为不同：

python
builder.add_edge(["b_2", "c"], "d")  # d runs once, after both b_2 and c complete
  • 起始节点列表会让 d 只在所列节点全部完成后运行一次。如果其中某个节点从未运行（例如条件边没有选择它的分支），d 就不会运行，也不会抛出错误。确实完成的分支所带来的状态更新仍保留在图状态中，但 d 不会消费它们。
  • 独立的边会在任一入边分支完成的每个超步中运行 d 一次。分支长度相等时只运行一次；分支长度不同时，d 会运行多次。
  • 配合 defer=True 的独立边（即上例中的模式）会在每个被选中的分支完成后运行 d 一次，无论扇出选中了全部分支还是只选中其中一部分。

defer=True 会把节点推迟到图中任何位置都没有待处理任务时，而不仅是供给它的那些分支。指向该节点的 1 仍会单独调用它。

条件分支#

在运行时根据状态路由到不同节点。节点 a 更新状态，然后条件边选择 b 或 c：

mermaid
%%{init:{'theme':'base','themeVariables':{'lineColor':'#40668D','primaryColor':'#E5F4FF','primaryTextColor':'#030710','primaryBorderColor':'#006DDD'}}}%%
flowchart LR
    startNode([START]) --> a[a]
    a -.-> b[b]
    a -.-> c[c]
    b --> endNode([END])
    c --> endNode

    classDef process fill:#E5F4FF,stroke:#006DDD,stroke-width:2px,color:#030710
    classDef terminal fill:#F2FAFF,stroke:#40668D,stroke-width:2px,color:#030710
    class a,b,c process
    class startNode,endNode terminal

虚线边表示条件路由。

如果你的扇出需要在运行时根据状态变化，可以使用 0 基于图状态选择一条或多条路径。参见下面的示例，其中节点 a 生成的状态更新决定了下一个节点。

python
import operator
from typing import Annotated, Literal, Sequence

from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    aggregate: Annotated[list, operator.add]
    # Branching key set by node a
    which: str


def a(state: State):
    print(f'Adding "A" to {state["aggregate"]}')
    return {"aggregate": ["A"], "which": "c"}


def b(state: State):
    print(f'Adding "B" to {state["aggregate"]}')
    return {"aggregate": ["B"]}


def c(state: State):
    print(f'Adding "C" to {state["aggregate"]}')
    return {"aggregate": ["C"]}


builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(c)
builder.add_edge(START, "a")
builder.add_edge("b", END)
builder.add_edge("c", END)


def conditional_edge(state: State) -> Literal["b", "c"]:
    # Fill in arbitrary logic here that uses the state
    # to determine the next node
    return state["which"]


builder.add_conditional_edges("a", conditional_edge)

graph = builder.compile()
python
result = graph.invoke({"aggregate": []})
print(result)
text
Adding "A" to []
Adding "C" to ['A']
{'aggregate': ['A', 'C'], 'which': 'c'}
💡提示

条件边可以路由到多个目标节点。例如：

python
def route_bc_or_cd(state: State) -> Sequence[str]:
    if state["which"] == "cd":
        return ["c", "d"]
    return ["b", "c"]

创建并控制循环#

循环需要一种停止的方式。常见模式是使用条件边，在满足终止条件时路由到 END。

你也可以在调用或流式输出时设置递归限制。该限制是 LangGraph 抛出错误之前允许的超步数量。参见递归限制概念。

以下示例使用一个简单的循环图。节点 a 要么继续到 b（b 又返回 a），要么退出：

mermaid

flowchart LR

    a -.-> b[b]
    a -.-> endNode([END])
    b --> a

    classDef process fill:#E5F4FF,stroke:#006DDD,stroke-width:2px,color:#030710
    classDef terminal fill:#F2FAFF,stroke:#40668D,stroke-width:2px,color:#030710
    class a,b process
    class startNode,endNode terminal

虚线边是条件路由。

💡提示

要在触及限制后捕获 GraphRecursionError，参见设置递归限制。要在触及限制前路由到完成路径，参见使用 RemainingSteps 处理递归。

添加一条编码终止条件的条件边：

python
builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)


def route(state: State) -> Literal["b", END]:
    if termination_condition(state):
        return END
    else:
        return "b"


builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "a")
graph = builder.compile()

要控制递归限制，请在配置中指定 "recursion_limit"。这会抛出 GraphRecursionError，你可以捕获并处理它：

python
from langgraph.errors import GraphRecursionError

try:
    graph.invoke(inputs, {"recursion_limit": 3})
except GraphRecursionError:
    print("Recursion Error")

定义一个带简单循环的图。条件边实现终止条件。

python
import operator
from typing import Annotated, Literal

from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    # The operator.add reducer fn makes this append-only
    aggregate: Annotated[list, operator.add]


def a(state: State):
    print(f'Node A sees {state["aggregate"]}')
    return {"aggregate": ["A"]}


def b(state: State):
    print(f'Node B sees {state["aggregate"]}')
    return {"aggregate": ["B"]}


# Define nodes
builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)


# Define edges
def route(state: State) -> Literal["b", END]:
    if len(state["aggregate"]) < 7:
        return "b"
    else:
        return END


builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "a")
graph = builder.compile()

这种架构类似于 ReAct 智能体，其中节点 "a" 是负责调用工具的模型，节点 "b" 代表工具。

route 条件边在 "aggregate" 列表超过阈值长度后结束运行。

调用该图时，它会在节点 "a" 与 "b" 之间交替，直到满足该条件。

python
graph.invoke({"aggregate": []})
text
Node A sees []
Node B sees ['A']
Node A sees ['A', 'B']
Node B sees ['A', 'B', 'A']
Node A sees ['A', 'B', 'A', 'B']
Node B sees ['A', 'B', 'A', 'B', 'A']
Node A sees ['A', 'B', 'A', 'B', 'A', 'B']

设置递归限制#

当无法保证终止条件时，请设置图的递归限制。LangGraph 在达到相应数量的超步后会抛出 GraphRecursionError。请捕获并处理该异常：

python
from langgraph.errors import GraphRecursionError

try:
    graph.invoke({"aggregate": []}, {"recursion_limit": 4})
except GraphRecursionError:
    print("Recursion Error")
text
Node A sees []
Node B sees ['A']
Node A sees ['A', 'B']
Node B sees ['A', 'B', 'A']
Node A sees ['A', 'B', 'A', 'B']
Recursion Error

import operator
from typing import Annotated, Literal

from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    aggregate: Annotated[list, operator.add]


def a(state: State):
    print(f'Node A sees {state["aggregate"]}')
    return {"aggregate": ["A"]}


def b(state: State):
    print(f'Node B sees {state["aggregate"]}')
    return {"aggregate": ["B"]}


def c(state: State):
    print(f'Node C sees {state["aggregate"]}')
    return {"aggregate": ["C"]}


def d(state: State):
    print(f'Node D sees {state["aggregate"]}')
    return {"aggregate": ["D"]}


builder = StateGraph(State)
builder.add_node(a)
builder.add_node(b)
builder.add_node(c)
builder.add_node(d)


def route(state: State) -> Literal["b", END]:
    if len(state["aggregate"]) < 7:
        return "b"
    else:
        return END


builder.add_edge(START, "a")
builder.add_conditional_edges("a", route)
builder.add_edge("b", "c")
builder.add_edge("b", "d")
builder.add_edge(["c", "d"], "a")
graph = builder.compile()

这个图是由超步组成的循环：先节点 A，再节点 B，然后节点 C 和 D 并发执行，之后回到 A。列表形式的边会等待 "c" 和 "d" 都完成后才返回 "a"。关于列表形式的边与分别指向同一节点的多条边有何区别，参见延迟节点执行。

在未设置递归限制的情况下调用，会在满足终止条件前完成两整圈：

python
result = graph.invoke({"aggregate": []})
text
Node A sees []
Node B sees ['A']
Node D sees ['A', 'B']
Node C sees ['A', 'B']
Node A sees ['A', 'B', 'C', 'D']
Node B sees ['A', 'B', 'C', 'D', 'A']
Node D sees ['A', 'B', 'C', 'D', 'A', 'B']
Node C sees ['A', 'B', 'C', 'D', 'A', 'B']
Node A sees ['A', 'B', 'C', 'D', 'A', 'B', 'C', 'D']

将递归限制设为四，则只能完成一圈，因为每圈是四个超步：

python
from langgraph.errors import GraphRecursionError

try:
    result = graph.invoke({"aggregate": []}, {"recursion_limit": 4})
except GraphRecursionError:
    print("Recursion Error")
text
Node A sees []
Node B sees ['A']
Node C sees ['A', 'B']
Node D sees ['A', 'B']
Node A sees ['A', 'B', 'C', 'D']
Recursion Error

访问并处理递归计数器#

节点可以从运行元数据中读取当前步骤。利用这一点在触及限制前做出反应。

python
from langchain_core.runnables import RunnableConfig


def my_node(state: dict, config: RunnableConfig) -> dict:
    current_step = config["metadata"]["langgraph_step"]
    print(f"Currently on step: {current_step}")
    return state

使用 RemainingSteps 处理递归

RemainingSteps 是仅 Python 支持的托管值，表示距离递归限制还剩多少步。使用它可以在 LangGraph 抛出 GraphRecursionError 之前路由到完成路径：

python
import operator
from typing import Annotated, Literal

from typing_extensions import TypedDict

from langgraph.graph import END, START, StateGraph
from langgraph.managed.is_last_step import RemainingSteps


class State(TypedDict):
    messages: Annotated[list, operator.add]
    remaining_steps: RemainingSteps


def reasoning_node(state: State) -> dict:
    remaining = state["remaining_steps"]
    if remaining <= 2:
        return {"messages": ["Approaching limit, wrapping up..."]}
    return {"messages": ["thinking..."]}


def route_decision(state: State) -> Literal["reasoning_node", "fallback_node"]:
    if state["remaining_steps"] <= 2:
        return "fallback_node"
    return "reasoning_node"


def fallback_node(state: State) -> dict:
    return {"messages": ["Reached complexity limit, providing best effort answer"]}


builder = StateGraph(State)
builder.add_node("reasoning_node", reasoning_node)
builder.add_node("fallback_node", fallback_node)
builder.add_edge(START, "reasoning_node")
builder.add_conditional_edges("reasoning_node", route_decision)
builder.add_edge("fallback_node", END)
graph = builder.compile()

result = graph.invoke({"messages": []}, {"recursion_limit": 10})

在图内部使用 RemainingSteps 处理限制，或在图外部捕获 GraphRecursionError：

方式检测时机处理位置控制流
主动方式（RemainingSteps）触及限制之前图内部，通过条件路由图继续走向完成路径
响应方式（GraphRecursionError）触及限制之后图外部，在 try / except 中图执行停止

相关元数据键包括 langgraph_node、langgraph_triggers、langgraph_path 和 langgraph_checkpoint_ns。

异步#

当 IO 密集型工作可以并发运行时，异步会很有帮助。要将同步图转换为异步图：

  1. 使用 async def 而不是 def 定义节点。
  2. 在这些节点内部对异步调用使用 await。
  3. 使用 .ainvoke 或 .astream 进行调用。

许多 LangChain 对象都实现了 Runnable 协议，该协议提供了同步方法的异步变体。异步流式输出示例请参阅流式输出指南。
