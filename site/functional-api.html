使用 Functional API 构建

Functional API 概述

了解 Functional API 的入口点与任务、检查点与重放的工作方式，以及如何避免常见的恢复陷阱。

Functional API 为普通函数赋予 LangGraph 的能力（持久化、记忆、人在回路 和 流式输出）。使用标准的语言控制流（if / else、循环和函数调用），而非声明由节点和边构成的图。

本页是入口点、任务、检查点与恢复规则的概念参考。关于设计思路的讲解，参见 以 Functional API 的方式思考。关于有序的构建路径，参见 Functional API 构建清单。

Functional API 使用两个构建模块：

  • @entrypoint：将函数标记为工作流的起点。它负责管理执行、中断和检查点。
  • @task：标记一个离散的工作单元（例如一次 API 调用）。任务返回一个类 future 对象，你可以等待它或用 .result() 解析。

Functional API 与 Graph API#

如果你已经选择了 Functional API，本节比较可以跳过。关于并排对比的决策指南，参见 在 Graph API 与 Functional API 之间做选择。两个 API 共享同一底层运行时，因此你可以在同一个应用中将它们结合使用。

高层差异：

  • 控制流：Functional API 使用标准的语言结构。Graph API 使用节点和边。
  • 状态：Graph API 需要声明状态，并且通常需要归并函数。Functional API 将状态限制在函数作用域内：任务通过返回值传递值，没有共享的状态模式。
  • 检查点：Graph API 在每个超步之后保存检查点。Functional API 将任务结果保存到入口点检查点。
  • 可视化：Graph API 支持图示意图。Functional API 不支持，因为图是在运行时构建的。

入口点#

@entrypoint 装饰器由函数创建工作流。它负责管理长时间运行的工作和中断。

定义#

当你需要持久化或人在回路时，传入检查点保存器。在配置中用 thread_id 标识每次运行。线程是一个会话或一次工作流运行的持久标识。

入口点是被 @entrypoint 装饰的函数。

该函数必须接受单个位置参数作为工作流输入。要传递多个值，请使用字典（或类似结构）作为该参数。

装饰该函数会生成一个工作流对象（一个 0 实例）。调用 invoke 或 ainvoke 来运行它。

python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint

checkpointer = InMemorySaver()


@entrypoint(checkpointer=checkpointer)
def my_workflow(name: str) -> str:
    return f"Hello, {name}"


config = {"configurable": {"thread_id": "1"}}
my_workflow.invoke("Alice", config)  # "Hello, Alice"
python
import asyncio

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint

checkpointer = InMemorySaver()


@entrypoint(checkpointer=checkpointer)
async def my_workflow(name: str) -> str:
    return f"Hello, {name}"


config = {"configurable": {"thread_id": "1"}}
asyncio.run(my_workflow.ainvoke("Alice", config))  # "Hello, Alice"
⚠警告

序列化 配置了检查点保存器时，入口点的输入和输出必须可 JSON 序列化。参见序列化。

运行与恢复#

调用 invoke 或 ainvoke 获取最终结果。关于流式输出，参见 使用 Functional API 进行流式输出。

在 0 之后，通过在 1 中传入恢复值来恢复。关于具体做法，参见为 Functional API 添加人在回路。

出现错误后，用 None 恢复同一个 thread_id。参见错误后的恢复。

短期记忆#

当 entrypoint 配置了 checkpointer 时，同一线程 id 上的连续调用会将状态存入检查点。

添加一个仅限关键字的 previous 参数。LangGraph 会将其设置为该线程上最后保存的值。首次运行时它是 None。要为下一次运行保存不同的值，请使用 2。参见返回不同的保存值。

关于累积和检查检查点，参见在线程上保存状态。

可注入参数#

在添加记忆或自定义流式输出之前，你可以跳过这一节。

声明 entrypoint 时，你可以请求 LangGraph 在运行时注入的额外参数：

参数描述
previous同一线程上一次调用的返回值（需要检查点保存器）。参见短期记忆。
config一个 0 对象，包含运行时配置值。
store一个 0 实例，用于长期记忆。也可通过 runtime.store 获取。
writer一个 StreamWriter，用于自定义流式输出。也可通过 runtime.stream_writer 获取。参见 使用 Functional API 进行流式输出。
runtime一个 0 对象，表示当前运行，包含上下文、存储和写入器。
⚠警告

请使用恰当的名称和类型注解来声明可注入参数。

请求可注入参数
python
from typing import Any

from langchain_core.runnables import RunnableConfig
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint
from langgraph.runtime import Runtime
from langgraph.store.memory import InMemoryStore

checkpointer = InMemorySaver()
store = InMemoryStore()


@entrypoint(
    checkpointer=checkpointer,
    store=store,
)
def my_workflow(
    some_input: dict,  # The input (for example, passed via `invoke`)
    *,
    previous: Any = None,  # Short-term memory from the previous invocation
    config: RunnableConfig,  # Run-time configuration
    runtime: Runtime,  # Context, store, and writer for the current run
) -> dict:
    memory_store = runtime.store
    writer = runtime.stream_writer
    return {
        "previous": previous,
        "some_input": some_input,
        "has_store": memory_store is not None,
        "has_writer": writer is not None,
        "thread_id": config["configurable"]["thread_id"],
    }

任务#

任务是离散的工作单元（例如，一次 API 调用或一个数据步骤）。任务有两个关键属性：

  • 并发执行：调用任务会立即启动它。只有当你等待结果时，入口点才会阻塞，因此独立的任务可以重叠执行。
  • 检查点：任务结果会被保存，以便恢复时能够还原它们。参见持久化。

定义#

使用 @task 装饰器定义任务：

python
from langgraph.func import task


@task
def slow_computation(input_value: int) -> int:
    # Long-running or side-effecting work
    return input_value * 2
⚠警告

序列化：任务的输出必须是 JSON 可序列化的，以支持检查点。

执行#

只能从入口点、另一个任务或 Graph API 节点中调用任务。不要在位于工作流之外的应用程序代码中调用它们。

调用任务会立即返回一个 future。使用 .result()（同步）或 await（异步）来获取结果。

python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task

checkpointer = InMemorySaver()


@task
def slow_computation(input_value: int) -> int:
    return input_value * 2


@entrypoint(checkpointer=checkpointer)
def my_workflow(some_input: int) -> int:
    future = slow_computation(some_input)
    return future.result()
python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task

checkpointer = InMemorySaver()


@task
async def slow_computation(input_value: int) -> int:
    return input_value * 2


@entrypoint(checkpointer=checkpointer)
async def my_workflow(some_input: int) -> int:
    return await slow_computation(some_input)

何时使用任务#

在以下情况下使用任务：

  • 检查点：保存长时间运行的结果，使恢复时不会重新计算它。
  • 人在回路：将暂停后不应重做的工作（例如 LLM 调用）包装在任务中。在中断后恢复会还原该结果。有关随机性，参见确定性。
  • 并行执行：并发运行独立的 I/O 密集型工作。
  • 可观测性：在 LangSmith 中跟踪离散步骤。
  • 重试：对离散的工作单元应用重试策略。参见配置 Functional API 任务。

恢复与检查点#

恢复重放取决于序列化、确定性和幂等性。

序列化#

配置检查点器时适用两条规则：

  1. entrypoint 的输入和输出必须是 JSON 可序列化的。
  2. task 的输出必须是 JSON 可序列化的。

使用 Python 基本类型，例如字典、列表、字符串、数字和布尔值。

序列化使任务结果和中间值能够为人在回路、容错和并行执行而恢复。配置检查点器时，不可序列化的值会引发运行时错误。

确定性#

恢复不会从执行停止的确切行继续。执行会返回到检查点边界，并向前重放，直到再次遇到暂停点。

对于 Functional API，重放从入口点的开头开始。LangGraph 会从检查点器还原已完成的任务和子图结果，而不是重新计算它们。这样可以在多次暂停之间保持步骤顺序，包括长时间运行或非确定性的任务输出。

对于人在回路，将非确定性工作（例如随机值）和副作用（例如文件写入或 API 调用）放入任务中。

不同的运行可能产生不同的结果。恢复特定线程时，应重放相同的已持久化任务和子图结果。

指导原则：

  • 避免重复工作：为入口点中的每个副作用分配其自己的任务，以便恢复时还原输出而不是重新运行它们。
  • 封装非确定性操作：将每次尝试之间会变化的值（随机数、实际时钟时间）保存在任务内部。
  • 使用幂等操作：有关部分失败和重试，参见幂等性。

幂等性#

幂等性意味着多次运行同一操作与运行一次的效果相同。将 API 调用和其他写入操作放在任务内部，并设计这些任务，使其在再次运行时是安全的。

恢复时，LangGraph 会还原已完成的任务结果。已开始但未完成的任务可能会再次运行，因此请使用幂等键，或在写入前检查现有结果。

暂停以进行人工审核#

此工作流会写一篇文章，并中断以进行人工审核：

python
import time

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt


@task
def write_essay(topic: str) -> str:
    """Write an essay about the given topic."""
    time.sleep(1)  # Placeholder for a long-running task.
    return f"An essay about topic: {topic}"


@entrypoint(checkpointer=InMemorySaver())
def workflow(topic: str) -> dict:
    """Write an essay and pause for review."""
    essay = write_essay(topic).result()
    is_approved = interrupt({
        # Any JSON-serializable payload. Surfaces as an Interrupt when streaming.
        "essay": essay,
        "action": "Please approve/reject the essay",
    })

    return {
        "essay": essay,
        "is_approved": is_approved,
    }

使用诸如 "cat" 的主题进行调用。该运行会写出文章，然后在 interrupt 处暂停。暂停可以无限期持续。恢复从入口点的开头开始。

write_essay 任务的结果会被还原，而不是重新计算。

有关流式输出、恢复和工具调用审核，参见使用 Functional API 添加人在回路。

常见陷阱#

处理副作用#

将副作用（写入文件、发送电子邮件）放在任务中，以便恢复时不会再次运行它们。

文件写入在入口点中运行，因此恢复时会第二次执行它。

python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint
from langgraph.types import interrupt

checkpointer = InMemorySaver()

@entrypoint(checkpointer=checkpointer)
def my_workflow(inputs: dict) -> int:
    # Runs again on resume.
    with open("output.txt", "w") as f:
        f.write("Side effect executed")
    value = interrupt("question")
    return value

副作用位于任务中，因此恢复会还原已检查点的结果。

python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt

checkpointer = InMemorySaver()

@task
def write_to_file() -> None:
    with open("output.txt", "w") as f:
        f.write("Side effect executed")

@entrypoint(checkpointer=checkpointer)
def my_workflow(inputs: dict) -> int:
    write_to_file().result()
    value = interrupt("question")
    return value

非确定性控制流#

将时间和随机性封装在任务中，以便恢复时返回相同的值。

  • 在任务中：获取随机数 (5) → 中断 → 恢复 →（再次返回 5）→ ...
  • 不在任务中：获取随机数 (5) → 中断 → 恢复 → 获取新的随机数 (7) → ...

在多次调用 0 时，LangGraph 会按索引将恢复值与每个中断匹配。如果恢复改变了中断的顺序，恢复值可能会附加到错误的中断上。参见确定性。

在入口点中读取时钟可能会改变恢复时运行的分支。

python
import time

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt

checkpointer = InMemorySaver()

@task
def slow_task(x: int) -> int:
    return x

@entrypoint(checkpointer=checkpointer)
def my_workflow(inputs: dict) -> dict:
    t0 = inputs["t0"]
    t1 = time.time()

    delta_t = t1 - t0

    if delta_t > 1:
        result = slow_task(1).result()
        value = interrupt("question")
    else:
        result = slow_task(2).result()
        value = interrupt("question")

    return {"result": result, "value": value}

在任务内部读取时钟，以便恢复时还原相同的时间戳和分支。

python
import time

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.func import entrypoint, task
from langgraph.types import interrupt

checkpointer = InMemorySaver()

@task
def slow_task(x: int) -> int:
    return x

@task
def get_time() -> float:
    return time.time()

@entrypoint(checkpointer=checkpointer)
def my_workflow(inputs: dict) -> dict:
    t0 = inputs["t0"]
    t1 = get_time().result()

    delta_t = t1 - t0

    if delta_t > 1:
        result = slow_task(1).result()
        value = interrupt("question")
    else:
        result = slow_task(2).result()
        value = interrupt("question")

    return {"result": result, "value": value}
